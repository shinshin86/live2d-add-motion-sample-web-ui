# live2d-add-motion-sample-web-ui

**Cubism Editorを使わず、JSONの追加・編集だけでLive2Dモデルにモーションを追加する**サンプルです。ブラウザで動くWebUI付き。

[English README is here](README.md)

## これは何?

Live2Dのモーション(`.motion3.json`)は、パラメータごとのキーフレームカーブを並べたただのJSONです。つまりリグやメッシュを触らなくても、**既存モデルが持っているパラメータの範囲内なら、テキスト編集だけで新しい動きを作れます**。

このリポジトリでは、Live2D公式サンプルモデル「ひより」に次の7モーションをJSONだけで追加しています。

| モーション | 主に使うパラメータ |
|---|---|
| 喜ぶ | 笑顔目(EyeSmile)+ 口角 + 頬 + 体のバウンス |
| ウィンク | 片目開閉 + 首かしげ |
| うなずき | 顔の上下角度(2回うなずき) |
| 考え中 | 首かしげ + 目線そらし + 眉ひそめ |
| びっくり | 目の見開き + 眉上げ + 「お」の口 + のけぞり |
| 照れる | 頬(照れ)+ うつむき + 伏し目 |
| 首ふり | 顔の左右角度の往復 |

再現性を重視して、モーションは手書きせず**生成スクリプト+独立バリデータ+ヘッドレスブラウザ検証**のパイプラインで作っています。AIエージェント(Claude Code / Codex等)に「新しいモーションを追加して」と頼めるよう、エージェント向けドキュメント([AGENTS.md](AGENTS.md))も同梱しています。

## クイックスタート

必要なもの: **Python 3**(標準ライブラリのみ)、**モダンブラウザ**、そして Claude Code / Codex などのコーディングエージェント

```bash
git clone https://github.com/shinshin86/live2d-add-motion-sample-web-ui.git
cd live2d-add-motion-sample-web-ui
```

リポジトリ直下でエージェントを起動し、**モデルの場所を添えて一言依頼するだけ**です:

> `~/Downloads/model.zip` にLive2Dモデルがあります。このモデルにモーションを追加して、ブラウザで確認できるようにしてください。

モデルの配置・セットアップ・モーション設計・生成・検証・サーバー起動まで、すべてエージェントが実行します(作業手順は [AGENTS.md](AGENTS.md) に定義してあり、エージェントが自動で読み込みます)。zipでもフォルダでも、置き場所はどこでも構いません。

モデルを持っていない場合は、公式サンプルモデル[「ひより・momose(hiyori_pro)」](https://www.live2d.com/learn/sample/momose-hiyori/)をダウンロードして試せます(同梱のサンプルモーション定義がそのまま使えます)。

モーションを追加・変更したいときも、依頼するだけです:

> このモデルに「手を振る」モーションを追加してください。既存パラメータで自然に作れない場合は、無理に作らず代替案を提案してください。

### 手動で実行する場合

```bash
python3 tools/setup_model.py <モデルのzipまたはフォルダ>   # 配置 + model.config.json 生成
python3 tools/gen_motions.py        # モーション生成 + 登録
python3 tools/validate_motions.py   # 検証(「OK」が出ること)

python3 tools/serve.py              # サーバー起動(8765番が使用中なら --port 8766 を付ける)
# → http://localhost:8765
```

モーション定義はモデルごとに `motion-defs/<モデル名>.py` に置きます(同梱のサンプル定義が例)。別のモデルではパラメータ構成に合わせて定義を新しく書く必要があります — その設計こそがAIエージェントに任せる部分で、定義ファイルは `models/` と同じ作業成果物としてgit管理外になっています(モデルを切り替えてもリポジトリにdiffは出ません)。

同梱の定義にローカルでモーションや表情を追加する場合は、同じ `define(curve, motion)`
形式で `motion-defs/<モデル名>.local.py` を作れます。本定義の後に追加され、名前の重複は
エラーになります。このファイルや `motion-defs/` 配下のローカル素材は git 管理外です。

## WebUIの使い方

- **今回追加したモーション**(★付きカード)のボタンで再生。既存モーションは折りたたみから展開
- アバターは**ドラッグで移動**、**ホイール/ピンチで拡大縮小**。「表示リセット」で初期配置に戻る
- カードは「単発アクション」と「ループ」に分かれています。再生中のモーションはボタンが強調され、単発なら「▶ 再生中」、ループなら点滅する「⟳ ループ中」と表示されます
- ループは「■ ループ停止」を押すか、別のモーションを再生するまで繰り返します。「ループ停止」はループの再生中だけ押せます
- 「リップシンク」欄を使うと、単発の表情にもループにも口の動きを重ねて、話しているときの見た目を確認できます。OFF(モーション自身の口の動き)、疑似(一定のリズム)、音声(ドロップまたは選択した音声ファイルの大きさに合わせる)、マイク(自分の声に合わせる)から選べます
- 操作パネルは「モーション」と「カメラ」の2つのタブに分かれています。ここまでの機能は「モーション」タブにあります。「カメラ」タブでは、自分の顔の動きでアバターを動かしたり、演技を録画したり、アバターだけを OBS に表示したりできます(詳しくは[カメラと配信モード](#カメラと配信モード))。タブを切り替えてもカメラは止まらないので、感情モーションを再生しながら顔で動かせます。カメラの動作中は、タブに赤い印が付きます
- デバッグ用クエリパラメータ: `?play=Action:0`(自動再生)/ `&freeze=1.2`(指定秒でポーズ固定)/ `&cycles=3`(ループモーションを3周で終了)/ `&lipsync=1`(疑似リップシンク。`&lipsync=mic` でマイク)/ `&audio=<URL>`(音声ファイルでリップシンク)/ `&tab=camera`(カメラのタブを開く)/ `&camera=1`(読み込み時にカメラを開始)/ `&fakeface=1`(カメラを使わず合成した顔の動きで動かす)/ `&record=N`(N 秒録画して保存。`&recordloop=1` でループとして保存、`&recordname=<名前>` でモーション名を指定)/ `?uitest=1`(ドラッグ・ズームの自動テスト)

### モデルの切り替え

`python3 tools/setup_model.py <モデルのzipまたはフォルダ>` で複数のモデルを配置し、`python3 tools/serve.py` を起動すると、操作パネルの上部に「モデル」の選択欄が表示されます。候補が2つ以上ある場合に使えます。通常の静的サーバーでは表示されません。カメラの録画中や未保存の録画がある間は、録画を停止し、保存または破棄してから切り替えてください。

モデルを選ぶと `model.config.json` が更新され、操作ページと配信ページが自動で再読み込みされます。`gen_motions.py`、`validate_motions.py`、録画の保存先も選んだモデルが対象になります。配信ページを特定のモデルに固定する場合は、`stream.html?model=models/hiyori_pro_t11/hiyori_pro_t11.model3.json` のようにパスを指定してください。

配置済みのモデルを切り替えるときは、選択欄を使ってください。同じモデルに `setup_model.py` を再実行すると作業用コピーが置き換わり、生成済みのモーションが消えます。その場合は `gen_motions.py` で再生成が必要です。

## 自分でモーションを追加するには

AIエージェントに任せる場合はクイックスタートの依頼例をそのまま使ってください(モーション名を変えるだけ)。手動でやる場合:

1. `python3 tools/analyze_model.py` — 使えるパラメータ・安全な値域・物理演算が管理するパラメータ(直接動かさない)を確認
2. `motion-defs/<モデル名>.py` にキーフレームを追記(書式は同梱サンプルを参照)
3. 生成 → 検証 → ブラウザ確認:

```bash
python3 tools/gen_motions.py
python3 tools/validate_motions.py
tools/verify_browser.sh   # ヘッドレスChromeでピーク時のポーズを撮影(要Chrome)
```

設計ルール(値域・基本姿勢復帰・物理パラメータ回避など)とモデル固有の知見は [AGENTS.md](AGENTS.md) にまとまっています。人間が読んでも役立ちます。

### 複数のモデルでモーションを使う

`motion-defs/shared/gestures.py` には、Hiyoriのサンプルをもとにした「うなずき・首ふり・びっくり」の共通定義があります。共通定義も `define(curve, motion)` で `(MOTIONS, MANIFEST)` を返します。時刻は秒、値は基本姿勢を `0`、安全な下限を `-1`、上限を `+1` として書きます。正負それぞれの側で幅を換算するため、基本姿勢が1、値域が `[-2,1]` のMouthFormなら、共通定義の `-0.5` は実際の値 `-0.5` になります。

使うモーションを `motion-defs/<モデル名>.py` または `.local.py` で選びます。

```python
SHARED_MOTIONS = {
    "gestures": {
        "nod": {},
        "shakehead": {"scale": 0.8, "label": "小さく首ふり"},
        "surprised": {"name": "my_surprised"},
    },
}
```

通常どおり生成・検証すると、Actionの末尾に追加されます。既存モーションの番号は変わりません。IDは省略すると `shared_<共通定義名>_<モーション名>` です。選ばなければ追加せず、メイン定義で選んだものをローカル定義で外す場合は、その項目を `False` にします。同じ項目の設定はローカル定義を優先して合成します。

`name` は英数字・`_`・`-` のファイル名、`label` は表示名、`scale` は動きの大きさです。`scale` は `[-1,1]` で、負の値なら向きが反転します。`parameters` に `{"ParamCheek": "ParamTere"}` のような対応を書けばモデルのIDへ置き換え、`None` にすればそのパラメータを使いません。置き換え元は、その共通モーションに含まれるIDを指定してください。

値域と基本姿勢はモデルに付属するモーションから調べ、参照のない標準IDには控えめな慣用値域を使います。モデルにないID、値域が不明なID、物理演算の出力は理由を表示して省きます。使えるパラメータが1つもない場合はエラーです。単発モーションは各曲線の先頭・末尾を `0` にし、ループは曲線とモーションの両方に `loop=True` を付けます。定義名の間違い、範囲外の値、変換先IDの重複、モデル別・ローカル・録画の定義との名前衝突は、ファイルを書き込む前にエラーにします。

`models/<モデル名>/.generated-shared-motions.json` は残してください。共通モーションの生成ファイルを記録し、選択を外した後も値域調査の参照に混ざるのを防ぎます。選択を外すと登録は解除され、生成済みファイルは残ります。共通モーションが管理していないファイルは上書きしません。検証ツールも、参照のない標準IDの値域と基本姿勢を独立に確認します。同じIDでも見た目や向きはモデルによって異なるため、各モデルで実際に再生して確認してください。

## 表情をモーションに重ねる

「モーション」タブの「表情」から選ぶと、再生中のモーションに表情を重ねられます。同じ表情をもう一度押すか「表情リセット」を押すと、フェードアウトして解除します。単発・ループ・リップシンクと併用でき、中継サーバーを使う場合は配信ページにも反映されます。

表情は `.exp3.json` として生成します。Hiyoriのサンプルでは、共通の「笑顔」「照れ」「びっくり」「ジト目」の後に、モデル固有の「ねむい」が並びます。このモデルは眉が前髪に隠れ、既存モーションにも怒り眉がないため、怒りの代わりに眠そうな表情を用意しています。追加する場合は `define(curve, motion)` の戻り値の3番目に辞書を加えます。

```python
EXPRESSIONS = {
    "custom_smile": {
        "label": "自分の笑顔", "fade_in": 0.4, "fade_out": 0.4,
        "parameters": [
            ("ParamEyeLOpen", 0, "Multiply"),
            ("ParamEyeROpen", 0, "Multiply"),
            ("ParamEyeLSmile", 1, "Overwrite"),
            ("ParamEyeRSmile", 1, "Overwrite"),
        ],
    },
}
return MOTIONS, MANIFEST, EXPRESSIONS
```

従来の `(MOTIONS, MANIFEST)` も引き続き使えます。ファイル名には英数字・`_`・`-` を使い、表示名は重複させないでください。各パラメータは `(ID, 値, 合成方法)` です。`Add` はモーションの値に加算、`Multiply` は乗算、`Overwrite` は上書きします。目の開きは `Multiply` にすると瞬きが保たれます。発話で口を動かす場合は、LipSync 用のパラメータを表情に含めないでください。フェードは省略すると0.4秒、表示名を省略するとファイル名になります。

通常どおり生成・検証すると、`models/<モデル名>/expressions/` にファイルができ、`FileReferences.Expressions` に登録されます。生成ツールは、自分が作った登録を `models/<モデル名>/.generated-expressions.json` に記録します。作業用モデルを使い続ける場合は、この管理ファイルも残してください。モデルに付属していた表情は変更せず、名前やファイルが衝突した場合はエラーにします。定義から外した表情は登録を解除しますが、生成済みファイルは残ります。

検証ツールは exp3 の形式、パラメータID、物理演算の出力、基本姿勢に合成した値を確認します。値域は既存モーションから調べ、参照がない標準IDには控えめな慣用値域を使います。再生時にはモデルの値域に収め、リップシンクの口の値を最後に反映します。

`?expression=smile` で起動時に表情を適用できます。ファイル名の拡張子を除いた部分か、表示名を指定してください。疑似リップシンク付きで、単独・モーション併用の画像を撮る例です。

```bash
OUT=tmp-verify/smile tools/verify_browser.sh --expression smile
OUT=tmp-verify/smile-nod tools/verify_browser.sh --expression smile Action:2 1.0
```

`OUT` は画像の出力先です。実行のたびに、そのフォルダの PNG を削除します。表情が見えることを画像で確認し、WebUI では切り替え・解除が滑らかに見えることも確認してください。

`tools/serve.py` で起動した場合、表情の選択・解除は `stream.html` にも届き、同じ表情ファイルのフェード時間で切り替わります。`?expression=` による選択も対象です。両ページとも顔の追跡の後に表情を重ね、最後にリップシンクを反映します。サーバーは最後に選んだ表情をメモリに保持し、後から開いた配信ページや再接続したページにも渡します。解除やモデル切り替えでこの状態を消し、サーバーの再起動時も引き継ぎません。途中参加したページで単発モーションを再生し直すことはありません。機能の更新後はサーバーを再起動し、両ページを再読み込みしてください。

中継するメッセージは `{"type":"expression","name":"smile"}`、解除は `name: null` です。`name` は登録した表情のファイル名から拡張子を除いた部分で、英数字・`_`・`-` の240文字以内です。番号や表示名を使わないため、並べ替えや表示言語の変更に影響されず、`?model=` で固定した配信ページも自分のモデルの登録と照合できます。該当がない場合や同名が複数ある場合は現在の表情を保ち、`?status=1` で理由を表示します。モデルを切り替えると、固定した配信ページの表情も解除します。ファイル読み込み中や送信待ちでも表情・再生・停止の順番を保ち、混雑時に省くのは姿勢メッセージだけです。録画編集の試再生は操作ページだけに反映します。

### 複数のモデルで表情を使う

共通定義も `(MOTIONS, MANIFEST, EXPRESSIONS)` を返せます。従来の2項目の戻り値も使え、表情だけの定義なら `({}, [], EXPRESSIONS)` とします。同梱の `motion-defs/shared/faces.py` には、HiyoriとHaruで表示を確認した「笑顔」「照れ」「びっくり」「ジト目」があります。共通モーションとは別に、モデルのメイン定義またはローカル定義で選びます。

```python
SHARED_EXPRESSIONS = {
    "faces": {
        "smile": {"name": "smile"},
        "shy": {"name": "shy"},
        "surprised": {},
        "glare": {"scale": 0.8},
    },
}
```

共通定義の表情辞書は通常の表情と同じ形式ですが、値は次のように扱います。

| 合成方法 | 共通定義の値と、生成する exp3 の値 |
|---|---|
| `Overwrite` | `[-1,1]` の目標値。`0` は基本姿勢、`-1` は安全な下限、`+1` は上限です。 |
| `Add` | `[-1,1]` の変化量。基本姿勢から、符号に応じた安全な上下限までの幅で換算します。exp3 には、換算後の目標値から基本姿勢を引いた値を書きます。 |
| `Multiply` | 目の開きを半分にする `0.5` など、そのままの有限な倍率です。正規化はしません。 |

Add/Overwrite は、まず `n *= scale` とし、`n` が0以上なら `基本姿勢 + n × (上限 - 基本姿勢)`、負なら `基本姿勢 + n × (基本姿勢 - 下限)` に換算します。Multiply の倍率は `1 + (倍率 - 1) × scale` です。`scale` は有限な `[-1,1]` の値で、`0` は変化なし、負の値は変化の向きを反転します。基本姿勢に合成した結果が安全な範囲を超える場合は、上下限に収めたことを表示し、合成方法に応じて exp3 の値を調整します。再生中の姿勢に重ねる際も、モデルの値域に収めます。

選択や設定の合成は `SHARED_MOTIONS` と同じです。ローカル定義の設定を優先し、`False` で無効にできます。`name`、`label`、`scale`、`parameters` に対応します。IDの初期値は `shared_<共通定義名>_<表情名>`、表示名には `共通: ` が付きます。宣言しなければ追加しません。モデルにないID、物理演算の出力、参照値域のない独自IDは理由を表示して省き、使えるパラメータがなければエラーにします。モデル別・ローカル・共通定義との名前や表示名の重複、付属の表情や管理対象外ファイルとの衝突は、書き込み前にエラーにします。

登録と画面の一覧は共通表情を先に並べ、その後にモデル付属の表情、モデル別・ローカル定義の表情が続きます。付属の表情同士の順番は保ちます。上の例は `name` でファイル名を維持するため、従来の `?expression=smile` / `shy` も使えます。表示名は「共通: 笑顔」「共通: 照れ」になり、モデル別の笑顔・照れの定義は外しています。モデル固有の表情はHiyoriが「ねむい」、Haruが「怒り」です。「にっこり目閉じ」は笑顔と重複するため削除しました。

Haruの笑顔・照れでは、`parameters` で `ParamCheek` を `ParamTere` に置き換えます。`ParamTere` の値域 `[0,1]` は既存モーションで確認しています。笑顔では `ParamBrowLY` / `ParamBrowRY` を `None` で省き、従来どおりモーションの眉を使います。共通の笑顔の赤面は、元の2モデルの値 `0.5` / `0.4` の間をとって `0.45` にしました。照れは眉の目標値を正規化し、MouthFormに `0.3` を掛けます。両モデルの基本値は `1` なので、基本姿勢では従来と同じ控えめな笑みになり、再生中はモーションの口の形を反映します。

管理には通常の表情と同じ `.generated-expressions.json` を使います。選択を外すと登録を解除し、生成済みファイルと所有記録は再利用のために残します。所有記録のある表情を共通定義へ移す場合は、同じファイル名を使えます。以前の登録だけを置き換え、付属の表情には手を加えません。この移行でも管理ファイルを残してください。管理対象外のファイルとの衝突はエラーにします。Actionの番号は変わりません。`--expression shared_faces_glare` や `?expression=共通:%20ジト目` を使い、各モデルで単独・モーション併用の両方を確認してください。「びっくり」は口の開きも指定しますが、発話中はリップシンクの値を優先します。「ドヤ顔」「困り顔」「恥ずかしい」は、共通パラメータだけでは両モデルで意図が伝わる見た目にならなかったため、同梱していません。

## ループモーション(発話中に感情を保つ用途など)

モーションを、継ぎ目なく繰り返せる形で生成できます。たとえば「悲しい」モーションを、キャラクターが話しているあいだ繰り返し再生し、その上でリップシンクを動かす使い方です。途中を切り出すのではなくモーション全体を繰り返し、終端から先頭へ戻るときも値が跳んだり動きが止まったりしません。

### 生成する

`motion-defs/<モデル名>.py` で、`motion()` と各 `curve()` の両方に `loop=True` を渡します。

```python
MOTIONS["sad_loop"] = motion(6.0, [
    curve("ParamAngleY", [(0, -15), (0.75, -12.5), (2.25, -17.5), (3.75, -12.5), (5.25, -17.5), (6.0, -15)], loop=True),
    curve("ParamBrowLForm", [(0, -0.8), (6.0, -0.8)], loop=True),
    # ...
], loop=True)
```

- 各カーブは、最後のキーを最初のキーと同じ値にします。`gen_motions.py` は、継ぎ目の前後で速度が変わらず、キーの値を行き過ぎない接線を付け、`Meta.Loop: true` を書き込みます
- 単発のアクションと違い、通常姿勢から始めて通常姿勢に戻す必要はありません。ずっと感情のポーズのままでも構いません
- `validate_motions.py` は継ぎ目を検査します。終端の値と傾きが先頭と一致しない場合はエラーになります
- 発話中に再生するループには、モデルの LipSync パラメータ(通常は `ParamMouthOpenY`)を含めないでください。含めると `validate_motions.py` が警告を出します。対象のパラメータは `analyze_model.py` で確認できます
- まばたきは目の開閉カーブに入れてください。モーションの再生中は自動まばたきが止まります

### アプリで再生する

Cubism Framework は `Meta.Loop` を読み込みますが、再生には反映しません。アプリ側で、モーションのインスタンスにループを指定する必要があります。使うのはモーションの公開 API だけなので、Live2D / Cubism のライブラリには手を加えません。この WebUI と同じ pixi-live2d-display の場合は次のとおりです。

```js
const mm = model.internalModel.motionManager;
const motion = await mm.loadMotion("Action", index); // pixi が再生するキャッシュ済みインスタンス
motion.setIsLoop(true);         // 終端で先頭に戻り、終了しない
motion.setIsLoopFadeIn(false);  // 周回ごとのフェードインを無効にする(有効だと継ぎ目で動きが滞る)
await model.motion("Action", index, PIXI.live2d.MotionPriority.FORCE);
```

- 2つのフラグは、モーションを開始する**前**に設定してください。公式の Cubism SDK for Web でも、`CubismMotion` の同じ2つのメソッドを使います。Unity やネイティブなど他のランタイムでは方法が異なる可能性があり、このリポジトリでは確認していません
- ループさせるのは、`Action` グループにあり `Meta.Loop: true` のモーションだけにしてください。Cubism Editor から書き出したモーションは、先頭と終端が一致していなくても `Meta.Loop: true` になっていることがよくあります
- FadeIn / FadeOut が効くのはループに入るときと抜けるときだけで、周回の間には入りません
- 止めるときは、別のモーションを開始するか(現在の姿勢からフェードインします)、`mm.stopAllMotions()` を呼びます。`motion.setIsLoop(false)` にすると、再生中の周回を最後まで再生してから終わります
- リップシンクは、モーションの更新後に毎フレーム口の値を書き込みます。たとえば `model.internalModel.on("beforeModelUpdate", ...)` の中で `coreModel.setParameterValueById("ParamMouthOpenY", v)` を呼びます
- ループを抜けた後の表情は、別のモーションで戻す必要があります。どのモーションも書き込まないパラメータは最後の値のまま残るため、顔のパラメータを設定するアイドルモーション(`Idle` グループ)がモデルに必要です

### 継ぎ目を確認する

```bash
tools/verify_browser.sh --loop Action:1   # 1〜3周目の継ぎ目の前後と周回の途中を、疑似リップシンク付きで撮影
```

継ぎ目の直前と直後の画像がほぼ同じで、ループの表情が保たれていれば問題ありません。WebUI では `?play=Action:1&cycles=3&lipsync=1` で、疑似リップシンク付きで3周再生してから止まります。

## カメラと配信モード

### カメラ

「カメラ」タブを開いて「● カメラ開始」を押すと、頭の向き、目の開閉、視線、口、眉、笑顔にアバターが合わせて動きます。最初に映った顔を正面の基準にします。基準を取り直すときは「正面をリセット」を押してください。感度、なめらかさ、左右反転も調整できます。感度の初期値は1.5、調整範囲は0.25〜3です。頭の動きに加えて口と眉にも効きますが、頭の角度は±30度以内に収めます。「映像を隠す」を押すと、トラッキングを続けたままカメラの映像を非表示にできます。スクリーンショットを撮るときなどに使ってください。この設定はブラウザに記憶されます。URL に `&preview=0` を付けると、最初から隠した状態で開きます。

顔の動きは、再生中のモーションに重ねて反映されます。たとえば悲しいループを再生すると、眉は悲しい形のまま、頭と口は自分の動きに合わせて動きます。

カメラの映像はブラウザ内(MediaPipe Face Landmarker を動かす Web Worker)で処理し、どこにも送信しません。MediaPipe 本体は jsDelivr から読み込み、バージョンを 0.10.21 に固定しています(これより新しい版には外部サービスへの計測送信が含まれるため)。顔検出のモデルは `vendor/mediapipe/` に同梱しています。

### 演技を録画してモーションにする

カメラの動作中に「● 録画開始」を押すと、顔の動きを最長60秒録画できます。もう一度押して録画を停止し、タイトル(日本語可、40字まで)を付けて保存してください。録画停止後はタイトル欄にカーソルが移ります。空欄のまま保存すると「録画 M/D HH:MM」がタイトルになります。ファイル名は `rec_YYYYMMDD_HHMMSS` で自動設定されるので、通常は変更不要です。変更する場合は「詳細設定(ファイル名)」を開いてください。英数字・`_`・`-` が使えます。不正な名前や重複した名前で保存すると、詳細設定が開いてエラーを表示します。話しながら再生する用途なら「ループとして保存」にチェックを入れます。

`python3 tools/serve.py` で起動している場合、保存すると録画を `motion-defs/recordings/<モデル名>/` に書き込み、モーションの生成と検証を自動実行します。このフォルダは git 管理外です。録画にはローカル時刻のオフセット付きで日時も保存されます。保存したモーションのボタンは、大きくタイトル、小さく「録画 M/D HH:MM」を表示します。古い録画はファイル名の日時を使い、日時が分からない場合はファイル名を表示します。完了後に「再読み込みして表示」を押すと、「モーション」タブの「保存したモーション」欄に表示されます。生成や検証が失敗しても録画は残ります。画面にエラーが表示されるので、サーバーのターミナルで詳細を確認してください。原因を修正し、以下のコマンドを実行してからページを再読み込みします。

アプリを更新したあとは、`tools/serve.py` を起動し直し、ブラウザでページを強制再読み込みしてください。古いサーバーを使っている場合は、保存前に検出して再起動を案内します。

ほかのサーバーで開いている場合は録画がダウンロードされます。`motion-defs/recordings/<モデル名>/` に移してから、次を実行してください。

```bash
python3 tools/gen_motions.py   # 録画が Action グループのモーションとして追加される
python3 tools/validate_motions.py
```

ページを再読み込みすると、保存したモーションが表示されます。

録画には各パラメータに対する顔の動きの分だけを記録するので、録画中にたまたま再生されていたアイドルや感情モーションは含まれません。generator がモデルの基本姿勢に重ね直し、既存モーションの値域に収め、キーフレームに間引いたうえで、最初と最後を基本姿勢へなめらかにつなぎます。ループの場合は、終わりを始まりへなめらかにつなぎ、リップシンク用のパラメータを除きます。こうして作ったモーションは、そのまま `validate_motions.py` を通ります。

### 上半身の動きを反映する

カメラを開始して「上半身も動かす」をONにすると、肩と胴体の向きからアバターの体を動かします。ページを開いた直後はOFFです。両肩と腰が映る位置に座ってください。最初に検出できた姿勢を正面とし、「正面をリセット」で顔と体を一緒に調整し直せます。感度・なめらかさ・左右反転も共通です。OFFにすると、従来の顔の向きに連動する体の動きへ戻ります。

肩と腰の位置から `ParamBodyAngleX/Y/Z` を動かし、変化量はそれぞれ±8・±6・±8度に抑えます。ONの間は顔の向きから作る体の動きを置き換え、顔の検出は続けます。検出の信頼度が低い場合や体を見失った場合は、徐々に中立へ戻します。腕とモデル固有の肩パラメータは、モデル間で自然に連続して動く対応を確認できていないため使いません。アバターを上半身だけ表示している場合も、カメラには腰まで入れる必要があります。

Pose Landmarker Liteのモデルは[ライセンス・チェックサム](vendor/mediapipe/README.md)とともに同梱し、ランタイムは0.10.21のままです。上半身の検出は顔とは別のCPU Workerで最大10fpsに抑え、処理に時間がかかる場合は間隔を広げます。処理中の画像は1枚だけにし、顔の画像転送は待たせません。映像や体のランドマークはブラウザ内にとどめ、計算した角度だけを録画やローカルのOBS中継に含めます。更新後は操作ページと配信ページの両方を再読み込みしてください。録画中は上半身のON/OFFを変更できません。既存の録画は書き換えません。

カメラなしで確認する場合は `?fakebody=1&bodytime=1` で疑似姿勢を固定できます。`bodytime=-1` なら反対の姿勢、省略すれば動き続けます。`&body=0` でOFF時と比較でき、`&fakeface=1` や既存の録画クエリとも併用できます。疑似姿勢だけでは実カメラの精度や処理速度は確認できないため、実際のカメラでは正面の調整、見失った後の復帰、顔の追従を確認してください。

### 保存した録画を編集する

「保存したモーション」の「編集」を押すと、元の録画内の開始・終了位置(秒)、速度(0.25〜4倍)、なめらかさ(0〜1)、ループの有無を変更できます。「試再生」は保存せずに確認するためのボタンです。操作ページだけで再生し、その間はカメラとリップシンクの入力を反映しません。「停止」で試再生を止められます。「編集を保存」で生成・検証したあと、「再読み込みして表示」を押すと一覧から再生できます。未保存の設定は編集を閉じると破棄されます。

「元の設定」を押すと、録画全体・通常速度・平滑化なし・録画時のループ設定に戻せます。その状態で保存すると、編集を取り消せます。編集内容は録画JSONの `edit` に保存し、元の `params`、録画時間、日時、ループ設定は書き換えません。

たとえば `{"trimStart":1,"trimEnd":6,"speed":1.5,"smooth":0.6,"loop":false}` は、元の1〜6秒を残して、約3.33秒で再生します。終了位置は「末尾から削る秒数」ではなく、残す区間の終わりです。生成時は切り出し、平滑化、速度変更の順に処理し、30fpsにそろえてから、従来と同じ基本姿勢への復帰やループの継ぎ目処理を行います。平滑化は前後5フレームの平均を使い、なめらかさで元の値との混ぜ具合を調整します。`edit` のない古い録画は従来と同じ結果になります。

「録画を削除」を押すと、編集画面内に確認が表示されます。「キャンセル」なら何も削除せず、「削除する」で元の録画と生成済みモーションを削除します。生成・検証に失敗した場合は削除を取り消します。成功後は再読み込みして一覧を更新してください。

編集には `tools/serve.py` が必要です。更新後はサーバーを起動し直し、ページを強制再読み込みしてください。`GET /live/status` の `recordingEdit: 1` が対応の目印です。既存の `recordingsVersion: 2` は変わりません。`/recordings/preview`、`/recordings/edit`、`/recordings/delete` に、同一オリジンのJSONとして `{model, id, edit}` をPOSTします(削除では `edit` 不要)。Hostはサーバーのポートを含むlocalhost/127.0.0.1に限り、録画保存・モデル切り替えと同じロックで処理します。試再生はファイルを保存しません。編集の保存後に生成・検証が失敗した場合は、設定を残してエラーを表示します。元のパラメータ値は保持されます。

### 配信モード(OBS)

1. `python3 tools/serve.py` でサーバーを起動します。配信モードにはこのサーバーが必要で、`python3 -m http.server` では中継できません
2. 「カメラ」タブの「配信モード」欄で背景(透明・緑・青)を選び、`stream.html` の URL をコピーします
3. OBS で「ブラウザ」ソースを追加し、その URL を指定します。操作ページと同じホスト名・ポートを使ってください(例: `http://localhost:8765/stream.html`)。表示サイズは900×800などに設定します

操作ページは開いたまま、カメラを動かしておいてください。顔の更新とリップシンクは描画とは独立した Worker の時計で処理するため、操作ページを OBS の背面に置いたり、最小化したりして使えます。「配信モード」欄にはサーバーへの配信接続数が表示され、未接続や送信失敗時は警告が出ます。

動かない場合は、OBS のソース URL に `?status=1` を付けて確認してください(すでに `?bg=green` などがある場合は `&status=1`)。「受信中」は顔などのパラメータが届いている状態です。「待機中」のままなら、URL、サーバー、操作ページのカメラを確認してください。アプリを更新したあとはサーバーを再起動し、操作ページと OBS のブラウザソースを再読み込みします。

OBS ではブラウザソースを右クリックして「対話」を開くと、アバターをドラッグで移動できます。ホイールやトラックパッドのピンチで、カーソル位置を中心に拡大縮小します。ダブルクリックで初期配置に戻ります。位置と倍率は配信ページ側でモデルごとに保存され、再読み込みや OBS の再起動後も復元します。ソースのサイズを変えたときも相対位置を保ちます。ストレージが使えない場合は操作できますが、配置は保存されません。

URL でも初期配置を指定できます。例: `stream.html?bg=green&zoom=1.2&x=0.5&y=0.55`。`zoom` は初期の表示サイズに対する倍率、`x` と `y` は画面の幅・高さに対するアバターの中心位置(0〜1)です。有効な URL の指定値は、読み込み時に保存値より優先されます。ダブルクリックすると URL で指定した配置に戻り、指定がなければ中央の初期配置に戻ります。モデルの実際のスケールは、操作ページと同じく0.05〜5に制限されます。

`stream.html` にはアバターだけが表示されます。操作ページで選んだ表情やモーション、カメラの顔の動き、リップシンクが、ローカルサーバーを通して反映されます。中継するのは再生の指示とパラメータだけで、カメラやマイクのデータは送りません。サーバーは 127.0.0.1 でのみ待ち受けます。

## ショートカットキーと外部アプリからの切り替え

操作ページが前面にあるとき、**1〜9** で表示順(単発 → ループ → 録画)の先頭9個の Action モーションを再生できます。再生中と同じキーを押しても、そのまま続けます。単発モーションが終わったあとに押すと、もう一度再生します。**0** または **Esc** で単発・ループどちらも止めて通常に戻します。ボタンをクリックした場合は、従来どおり最初から再生し直します。

「モーション」タブの **ショートカットキー** を開くと、10個目以降や録画を含むすべての Action モーションにキーを割り当てられます。各行のキーボタンを押してから、使いたいキーを押してください。Shift・Alt との組み合わせやテンキーも使えます。Esc で変更をキャンセル、Backspace・Delete で解除します。使用中のキーを別の行に割り当てると、元の行から移ります。Ctrl・Command との組み合わせは割り当てできません。入力欄への文字入力中、Ctrl・Command を押しているとき、キーの長押しによる連続入力では再生しません。Esc は入力中・割り当て待ち以外では常に「通常に戻す」として使えます。

設定は、モデルの URL ごとにこのブラウザに保存します。モーションIDを使うため、一度編集した割り当てはモーションが増えてもずれません。追加分は未割り当てになります。「初期の割り当てに戻す」で最初の状態に戻せます。ブラウザの保存機能が使えない場合、そのページでは設定できますが、再読み込みすると初期値に戻ります。

OBS など別のアプリが前面にあるときに切り替えるには、`python3 tools/serve.py` で起動し、操作ページを開いたままにします。**ショートカットキー → 外部アプリから切り替え** から URL・トークン・curl 例をコピーしてください。curl 例のモーションは選択欄で変更できます。「通常に戻す」用のコピーもあります。更新後に案内が出た場合は、サーバーを再起動して操作ページを再読み込みしてください。

**ターミナルから試す:** サーバーを起動して http://localhost:8765 を開いたまま、リポジトリのフォルダで次を実行します。トークンは `$(cat .live-token)` で自動的に読み込みます。`hiyori_happy` は同梱サンプル(Hiyori)のモーションです。ほかのモデルでは、モーションボタンに小さく表示されている ID か、表示名に置き換えてください。`--port` を付けてサーバーを起動した場合は、`8765` をそのポート番号に変えてください。

```sh
# モーションを再生する
curl -X POST http://localhost:8765/live/motion -H "X-Live-Token: $(cat .live-token)" -H "Content-Type: application/json" -d '{"motion":"hiyori_happy"}'

# 通常に戻す
curl -X POST http://localhost:8765/live/motion -H "X-Live-Token: $(cat .live-token)" -H "Content-Type: application/json" -d '{"stop":true}'
```

何も表示されずに終われば成功で、ページのアバターが動きます。「操作ページが開いていません」と出たら操作ページを開いてください。「トークンが一致しません」と出たら、リポジトリのフォルダで実行しているか確認してください。

ほかのアプリから送るときのリクエストの形は次のとおりです。

```sh
curl -X POST http://localhost:8765/live/motion \
  -H 'X-Live-Token: <token>' -H 'Content-Type: application/json' \
  -d '{"motion":"<motion-id>"}'

curl -X POST http://localhost:8765/live/motion \
  -H 'X-Live-Token: <token>' -H 'Content-Type: application/json' \
  -d '{"stop":true}'
```

`X-Live-Token` の代わりに `Authorization: Bearer <token>` も使えます。モーションIDはファイル名から `.motion3.json` を除いたものです。表示名の完全一致でも指定できますが、IDの一致を優先します。同じ表示名が複数ある場合は `409` になるので、IDで指定してください。再生中と同じモーションの再送では再生を続けます。成功時の `204` は操作ページへの送信待ちに入ったことを示し、再生完了の確認ではありません。トークンの欠落・不一致は `401`、モーションがなければ `404`、操作ページが未接続なら `503` を返します。保存したばかりのモーションが操作ページに表示されていない場合は、ページを再読み込みしてください。外部指定の対象は `model.config.json` のモデルです。

**Stream Deck:** バックグラウンドで Web リクエストを送るプラグインのアクションを使い、上記の POST・URL・JSON の Content-Type・トークンヘッダ・ボディを設定します。標準の Website アクションはタブを開くだけなので、この操作には使えません。

**macOS ショートカット:** 「設定 → 詳細」でスクリプトの実行を許可し、「シェルスクリプトを実行」に curl コマンドを貼り付け、ショートカットの詳細からキーボードショートカットを割り当てます。前面のアプリによっては反応しない場合があります。アプリを問わず使いたい場合は、Raycast・Hammerspoon から同じコマンドを実行するか、Stream Deck を使ってください。

ショートカット・Raycast・Hammerspoon はリポジトリのフォルダでコマンドを実行しないため、`$(cat .live-token)` ではトークンを読み込めません。設定画面の「モーションの curl 例をコピー」でコピーしたコマンドを貼り付けてください。トークンが直接書き込まれています。

トークンは `.live-token`(git 管理外)に保存され、サーバーを再起動しても変わりません。「トークンを再生成」を押すと古いトークンは `401` になるので、外部アプリの設定も更新してください。サーバーは `127.0.0.1` だけで待ち受け、トークン・モーションのエンドポイントは Host が `localhost:<port>` または `127.0.0.1:<port>` のリクエストだけを受け付けます。操作ページは `/live/commands` で外部操作を受け取り、OBS 用の `/live/events` とは別に接続します。ページを閉じたことが接続数に反映されるまで、keepalive を待つ場合があります。

## リポジトリ構成

```
index.html                  WebUI(静的HTML、ビルド不要)。model.config.json からモデルを解決
stream.html                 配信用ページ(アバターのみ。OBS 向け)
web/                        WebUI のモジュール(JSDoc で型を付けた JavaScript。ビルド不要):
                            カメラトラッキング、録画、配信の中継、ループ再生
vendor/mediapipe/           カメラトラッキングで使う MediaPipe の顔・姿勢検出モデルとライセンス
tools/
  serve.py                  ローカルサーバー(静的ファイルの配信、stream.html への中継、録画の保存)
  setup_model.py            モデル配置(zip/フォルダ → models/)+ model.config.json 生成
  analyze_model.py          パラメータ・値域・物理出力の分析
  gen_motions.py            生成エンジン(モデル非依存)。定義から生成+登録(冪等)
  shared_motions.py         共通定義の正規化値をモデルごとの値へ変換
  shared_expressions.py     共通表情を合成方法に応じてモデルの安全な値域へ変換
  validate_motions.py       独立実装のバリデータ
  verify_browser.sh         ヘッドレスChromeでの実描画検証(--loop: 継ぎ目の確認) ※macOSのChromeパスを想定(env CHROME で変更可)
motion-defs/<モデル名>.py    モーション定義(モデルごとの創作物) [git管理外・同梱サンプルのみ追跡]
motion-defs/shared/*.py     モデル間で使う正規化済みの共通定義 [追跡対象]
AGENTS.md                   AIエージェント向け作業ガイド
model.config.json           [git管理外] 現在のモデル設定(setup_model.pyが生成)
local-assets/ , models/     [git管理外] Live2Dモデルデータ(ライセンス上、非同梱)
```
